College Project Overview

EventBuddy – Technical Specification

1. Problem Statement

In college symposiums, tech fests, and cultural summits, event coordinators are overwhelmed by hundreds of repetitive volunteer inquiries regarding dates, schedules, venues, and duty assignments. Manual WhatsApp coordination leads to misplaced responsibilities and confused volunteers.

2. Project Solution

EventBuddy delivers a centralized web portal integrating an autonomous rule-based inquiry chatbot and an administrative coordinator dashboard. Volunteers can self-register via a conversational wizard, obtain verified duty slips, and check schedules 24/7. Coordinators gain live metrics, role tracking, and task delegation.

3. System Architecture & Tech Stack

  • Frontend Presentation: Semantic HTML5, accessible ARIA landmarks, mobile responsive CSS3 with CSS Custom Properties.
  • Client-Side Engine: Vanilla JavaScript (ES6+ modular object architecture). Zero heavy external framework dependencies.
  • Chatbot Matcher: Deterministic Intent Classifier utilizing regular expressions, keyword weighting, and finite-state dialogue management.
  • Persistence Layer: HTML5 localStorage API for instant client-side CRUD persistence without requiring paid backend subscriptions.
Exam Preparation

Third-Year Viva Questions & Answers

Q1: Why use a Rule-Based Chatbot instead of OpenAI/LLM API?
Rule-based chatbots guarantee deterministic, reliable answers without hallucinations, require zero operational cost or API tokens, respect student privacy without sending data to external servers, and work completely offline/locally.
Q2: How does the conversational registration wizard work?
It implements a Finite State Machine (FSM). The state advances from Name → Email → Department → Year → Role → Shift. Each state validates the input before transitioning to the next and committing to localStorage upon completion.
Q3: What are the limitations of localStorage in this project?
localStorage is scoped to the specific browser domain and client machine (approx 5MB limit). It is ideal for demonstration and offline testing. For production multi-user deployment, a REST API with Node.js/Python and a PostgreSQL/MongoDB database would replace localStorage without changing frontend presentation.
Q4: How does EventBuddy prevent duplicate registrations?
During registration (both in the form and conversational bot), the system checks existing volunteer records by normalized email address. If an existing registration is detected, a friendly warning is returned with the volunteer's existing ID.
